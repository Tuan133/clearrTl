File       : backend/.env
Mức độ     : CRITICAL
CWE        : CWE-312 (Cleartext Storage of Sensitive Information)

Vấn đề:
  File backend/.env chứa credentials thật được commit vào repository:
  - MONGO_URI: mongodb+srv://thinhvatuan05_db_user:kERYdALaXWqamcxM@cluster0.bmvv6fy.mongodb.net/...
    → Lộ username + password của MongoDB Atlas
  - JWT_SECRET: tlaundry_super_secret_jwt_key_2026_secured_889922
    → Lộ secret key, attacker có thể forge JWT token tùy ý
  - JWT_REFRESH_SECRET: tlaundry_refresh_super_secret_key_2026_rt_009988
    → Lộ refresh secret, attacker forge refresh token vô thời hạn

  2. KHÔNG commit .env chứa giá trị thật. Chỉ commit .env.example với placeholder

  4. Dùng secret manager (AWS Secrets Manager, Doppler, Vault) ở production
  5. JWT_SECRET phải dài ≥64 ký tự random (entropy cao), không phải chuỗi có nghĩa

[C-02] JWT SECRET YẾU & CÓ THỂ ĐOÁN ĐƯỢC
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
File       : backend/.env, backend/middleware/auth.js (dòng 17)
Mức độ     : CRITICAL
CWE        : CWE-330 (Use of Insufficiently Random Values)

Vấn đề:
  JWT_SECRET = "tlaundry_super_secret_jwt_key_2026_secured_889922"
  - Là chuỗi có pattern rõ ràng, predictable, không có đủ entropy
  - JWT_REFRESH_SECRET có fallback nguy hiểm: process.env.JWT_SECRET + '_refresh'
    → Nếu JWT_REFRESH_SECRET không được set, secret refresh chỉ là JWT_SECRET + "_refresh"
    → Attacker biết JWT_SECRET có thể tính ra JWT_REFRESH_SECRET

Tác động:
  - Brute force hoặc dictionary attack có thể crack được secret
  - Forge JWT token hợp lệ để đăng nhập bất kỳ tài khoản nào (kể cả ADMIN)

Khắc phục:
  1. Tạo secret ngẫu nhiên: node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
  2. Xóa fallback "_refresh" trong auth.js dòng 17, bắt buộc phải có JWT_REFRESH_SECRET riêng biệt
  3. Kiểm tra khi start server: nếu JWT_SECRET chưa set hoặc ngắn < 32 chars → throw error, không start

[H-01] TOKEN LƯU TRONG LOCALSTORAGE - DỄ BỊ XSS ĐÁNH CẮP
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
File       : frontend/src/services/api.js (dòng 6-15)
             frontend/src/context/AuthContext.jsx (dòng 13-14)
Mức độ     : HIGH
CWE        : CWE-922 (Insecure Storage of Sensitive Information)
OWASP      : A02:2021 Cryptographic Failures

Vấn đề:
  Access Token và Refresh Token được lưu trong localStorage:
    localStorage.setItem('tlaundry_token', accessToken)
    localStorage.setItem('tlaundry_refresh_token', refreshToken)
    localStorage.setItem('tlaundry_user', JSON.stringify(user))

  localStorage có thể bị đọc bởi bất kỳ JavaScript nào chạy trên cùng domain,
  bao gồm script từ XSS attack hoặc third-party scripts (analytics, ads, CDN bị compromise).

Tác động:
  - Nếu có bất kỳ XSS nào (dù nhỏ) → toàn bộ session bị đánh cắp
  - Refresh token 30 ngày bị đánh cắp → attacker duy trì quyền truy cập 30 ngày
  - Không có cơ chế tự động revoke khi detect stolen token

Khắc phục:
  - Lưu accessToken trong memory (JavaScript variable) thay vì localStorage
  - Lưu refreshToken trong HttpOnly cookie (không thể đọc bằng JS)
  - Cấu hình cookie: { httpOnly: true, secure: true, sameSite: 'Strict' }
  - Nếu dùng SPA không thể dùng cookie: implement token rotation + short expiry (5-15 phút)

[H-03] RATE LIMIT BỊ BỎ QUA HOÀN TOÀN TRONG MÔI TRƯỜNG DEV
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
File       : backend/server.js (dòng 89-103)
Mức độ     : HIGH
CWE        : CWE-307 (Improper Restriction of Excessive Authentication Attempts)

Vấn đề:
  skip: (req) => isDev || req.ip === '127.0.0.1' || req.ip === '::1' || ...

  Trong development (NODE_ENV !== 'production'), toàn bộ rate limiting bị disable.
  Nếu production server vô tình chạy với NODE_ENV=development (hoặc không set),
  rate limiting bị tắt hoàn toàn.

  Hơn nữa, general limiter cho phép 1000 requests/15 phút — quá cao,
  chỉ auth limiter là 100/15 phút nhưng chưa đủ bảo vệ.

Tác động:
  - Brute force đăng nhập không giới hạn nếu NODE_ENV không phải 'production'
  - Credential stuffing attacks dễ thực hiện
  - DoS/DDoS trên các endpoint public

Khắc phục:
  - Bỏ điều kiện skip isDev hoặc chỉ skip localhost trong dev, không skip trên staging/prod
  - Validate NODE_ENV='production' được set đúng trong deployment pipeline
  - Auth limiter giảm xuống 10-20 lần/15 phút (OWASP recommendation)
  - Implement account lockout sau N lần thất bại
  - Xem xét dùng Redis store cho rate limit thay vì in-memory (để horizontal scaling)

[H-04] MẬT KHẨU YẾU ĐƯỢC PHÉP (TỐI THIỂU 6 KÝ TỰ)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
File       : backend/middleware/validate.js (dòng 17-19)
Mức độ     : HIGH
CWE        : CWE-521 (Weak Password Requirements)
OWASP      : A07:2021 Identification and Authentication Failures

Vấn đề:
  const passwordField = z.string().min(6, '...').max(100, '...')
  
  Chỉ yêu cầu 6 ký tự, không có yêu cầu về:
  - Chữ hoa / chữ thường
  - Ký tự số
  - Ký tự đặc biệt
  → Cho phép password "123456", "abcdef", "password" — các password phổ biến nhất thế giới

Tác động:
  - Brute force / dictionary attack thành công dễ dàng
  - Credential stuffing từ danh sách password leaked databases

Khắc phục:
  - Tối thiểu 8 ký tự (NIST SP 800-63B recommendation: 8, tốt hơn là 12)
  - Yêu cầu ít nhất 1 chữ hoa + 1 số + 1 ký tự đặc biệt
  - Kiểm tra password không nằm trong danh sách common passwords (có thể dùng zxcvbn library)
  - Implement: .regex(/^(?=.*[A-Z])(?=.*\d)(?=.*[!@#$%^&*]).{8,}$/, 'Password không đủ mạnh!')

[M-01] KHÔNG CÓ CSRF PROTECTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
File       : backend/server.js
Mức độ     : MEDIUM
CWE        : CWE-352 (Cross-Site Request Forgery)
OWASP      : A01:2021 Broken Access Control

Vấn đề:
  Hệ thống không có bất kỳ CSRF token nào. Tuy nhiên mức độ được giảm xuống MEDIUM

Mức độ     : MEDIUM
CWE        : CWE-319 (Cleartext Transmission of Sensitive Information)

Vấn đề:

    contentSecurityPolicy: {
      directives: {
        defaultSrc: ["'self'"],
        scriptSrc: ["'self'"],
        styleSrc: ["'self'", "'unsafe-inline'"],
        imgSrc: ["'self'", "data:"],
        connectSrc: ["'self'", "https://api.tlaundry.vn"]

    }
  }));

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Mức độ     : MEDIUM

  - limit=999999 → query toàn bộ DB trong 1 request → DoS / memory exhaustion
  - page=-1 → .skip(-1 * limit) → MongoDB behavior không xác định
  - Không sanitize status, role query params → tuy MongoDB sanitize đã có, nhưng thiếu whitelist

Khắc phục:
  const page = Math.max(1, parseInt(req.query.page) || 1);
  const limit = Math.min(100, Math.max(1, parseInt(req.query.limit) || 20));
  - Validate status chỉ thuộc enum hợp lệ trước khi query
